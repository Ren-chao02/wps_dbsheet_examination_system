# 考试设置向导改造设计文档

## 背景

当前系统的考试创建流程存在以下问题：

1. `ExamWizard.tsx` 是一个 5 步全页面向导，但提交时只保存了考试基本信息和试卷绑定，场次、考场、学生分配均未真正持久化。
2. 新增考试时没有强制关联批次，导致考试与批次管理体系脱节。
3. 学生端 `/api/my-exams` 只返回 `published/in_progress/ended` 状态的考试，很多教师误以为创建完考试学生就能看到，实际上漏掉了「发布」步骤。

本次改造目标是：

- 新增考试必须强制关联批次。
- 参考产品截图，将创建流程改为弹窗式 3 步设置向导（绑定试卷 → 考场监考设置 → 考生设置）。
- 每步配置都能真正保存到数据库，而不是仅停留在前端状态。

## 设计方案

### 1. 交互流程

1. 教师在「考试管理」列表页点击「新增考试」。
2. 弹出 `ExamConfigWizard` 弹窗，第 0 步为「选择批次」。
3. 必须选择一个已有批次，否则「下一步」按钮禁用。
4. 选择批次并点击「下一步」后，前端调用 `POST /api/exams` 创建一个 `status = draft` 的草稿考试，考试名称使用默认值（如 `未命名考试-{timestamp}`），并关联选中的 `batchId`。
5. 向导进入第 1 步「绑定试卷」。
6. 后续每切换一步，自动保存当前步骤数据到后端。
7. 点击「完成」后关闭弹窗，考试仍保持草稿状态；教师需在考试列表页手动点击「发布考试」。

### 2. 弹窗向导步骤

| 步骤 | 标题 | 核心功能 |
|------|------|----------|
| 0 | 选择批次 | 下拉选择已有批次；创建草稿考试 |
| 1 | 绑定试卷 | 试卷筛选表格；选择并绑定 `paperId` |
| 2 | 考场监考设置 | 新增考场；为考场分配监考老师；按考场展示列表 |
| 3 | 考生设置 | 新增/导入/移除考生；按考场分配考生座位 |

### 3. 组件结构

```
packages/client/src/pages/teacher/
├── ExamConfigWizard/          # 弹窗向导容器
│   ├── index.tsx              # Modal + Steps 状态控制
│   ├── BatchSelectStep.tsx    # 第 0 步：批次选择
│   ├── PaperBindStep.tsx      # 第 1 步：绑定试卷
│   ├── RoomInvigilationStep.tsx # 第 2 步：考场与监考
│   └── StudentAssignStep.tsx  # 第 3 步：考生分配
```

### 4. 数据保存策略

每步切换时自动保存，允许用户随时关闭弹窗并在后续通过「编辑/设置向导」继续配置。

- 第 0 步：创建草稿考试 `POST /api/exams`，携带 `batchId`。
- 第 1 步：更新考试 `PUT /api/exams/:id`，携带 `paperId`。
- 第 2 步：
  - 新增考场 `POST /api/rooms`（携带 `examId`）。
  - 分配监考老师 `POST /api/rooms/:id/invigilators/:userId`。
- 第 3 步：
  - 批量分配考生 `POST /api/rooms/:id/students/batch-assign`。
  - 移除考生 `DELETE /api/rooms/:id/students/:studentId`。

### 5. 与现有页面关系

- **新增考试**：完全走新的弹窗向导。
- **编辑考试**：保留现有 `ExamForm.tsx` 编辑页，但增加「打开设置向导」入口，方便继续配置考场/考生。本次改造优先保证新增流程可用。
- **考试管理列表页**：「创建考试」按钮改为打开弹窗向导，不再跳转到 `ExamWizard.tsx` 全页面。

### 6. 后端改动

后端 API 基本已具备所需能力：

- `POST /api/exams` 已支持 `batchId` 字段。
- `POST /api/exams/:id/publish` 已存在。
- `POST /api/rooms` 支持 `examId`。
- `POST /api/rooms/:id/invigilators/:userId` 已存在。
- `POST /api/rooms/:id/students/batch-assign` 已存在。

需要确认或微调的点：

- `POST /api/exams` 的 `examSchema` 当前未包含 `batchId`，需要加入。
- 创建草稿考试时，`title` 为必填字段。前端需要提供一个默认标题，或后端允许空标题并在保存时生成默认值。本设计采用前端生成默认标题。

### 7. 错误处理

- 批次未选择：下一步按钮禁用，并提示「请先选择批次」。
- 创建草稿考试失败：停留在第 0 步，显示错误信息。
- 某一步保存失败：显示错误提示，不自动跳转到下一步。
- 关闭弹窗后重新打开：通过 `examId` 拉取当前考试配置，恢复已保存状态。

### 8. 边界情况

- 用户在第 0 步创建草稿后关闭弹窗：考试以草稿形式保留在列表中，可继续编辑。
- 用户未配置试卷/考场/考生即关闭：考试仍是草稿，但发布时会因缺少题目而失败（后端已校验）。
- 批次被删除：草稿考试关联的 `batchId` 失效，编辑时提示重新选择批次。

## 验收标准

- [ ] 考试管理页点击「新增考试」弹出 Modal 向导。
- [ ] 向导第 0 步必须选择批次，未选择无法进入下一步。
- [ ] 选择批次后自动创建草稿考试并关联批次。
- [ ] 向导包含「绑定试卷」「考场监考设置」「考生设置」三步。
- [ ] 每步数据能保存到数据库，刷新后数据不丢失。
- [ ] 向导完成后，考试在列表中显示为草稿状态。
- [ ] 现有发布、开始、结束功能不受影响。

## 未包含在本次范围

- 删除现有 `ExamWizard.tsx` 全页面向导（保留作为兼容入口，后续可移除）。
- 在弹窗内新增批次（如需，可在批次管理页先创建）。
- 复杂字段如「自动组卷方案」「考生抽卷几率」「绑卷状态」等高级功能，本期仅实现基础试卷绑定，UI 保留列占位。
