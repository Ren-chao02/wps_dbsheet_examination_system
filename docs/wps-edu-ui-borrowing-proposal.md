# 「WPS 教学平台」UI/UX 借鉴方案（草案）

> 调研对象：https://edu.wps.cn/app/study-platform（教师端 + 学生端）、官方操作手册 https://p.kdocs.cn/s/2OXD2DZIADAB6
> 调研方式：真站登录后逐页截图（test_screenshots/wps-ref/live-*.png）+ 手册全量翻页 OCR/截图复核（manual-imgs/M-*.png）
> 结论用途：确认「抄什么、怎么抄、不抄什么」后再动代码。

---

## 一、总体判断

**可以借鉴，而且价值很大——但要挑着抄。** 三条判断：

1. **信息架构层面**：参考产品是「课程中心」模型（课程下挂 测验/考试/班级/监考/成绩），我们是以考试为中心的独立模块。整体 IA 不照搬，但**「学生首页的待办聚合」和「考试详情内聚一切」两个结构可直接吸收**。
2. **视觉与组件层面**：他们的设计语言（浅灰底 + 白卡 + 大圆角 + 柔和多彩 KPI 卡 + 插画空状态）比我们更统一、更"产品化"。我们有 Apple 风皮肤但沉浸式考试页还残留旧 antd 蓝，**先统一自身，再吸收他们的卡片/空状态/列表行设计**。
3. **考务业务细节层面**（最值钱）：场次/考场层级表、抽卷几率、考生动态时间线、续考/强制交卷、成绩表「缺考/是否作弊/重新算分」、发布方式带后果说明、名单导入的注意事项文案——**这些是与我们业务同构、可直接对照补齐的产品细节**。

## 二、参考产品速写

### 2.1 信息架构

**教师端**（左侧图标栏 + 可展开完整菜单，导航即自动收起）：

```
首页（工作台）          我的课程          在线考试          监考管理
官方资源 ▾（官方题库/官方试卷库/官方课程库）
校本资源 ▾（校本题库/校本试卷库/校本组卷方案）
任务中心
─────────────── 底部：切换到学生端 ｜ 用户信息（角色标签+学校）
```

**学生端**极简：`首页 / 我的课程` 两项；考试与测验全部沉在课程与首页待办卡里。

**课程内页**（教师）二级 tab：课程介绍 / 课程学习 / 实训测验 / 课程班级 / 在线考试 / 监考管理 / 学习统计 / 成绩管理。

### 2.2 设计语言

| 维度 | 参考产品 | 我们现状 |
| --- | --- | --- |
| 主色 | 深蓝 #2663db/#2b5cff | #007aff（布局层）与 #1890ff（沉浸页）并存 |
| 页面底 | #f5f7fa 浅灰，白卡大圆角 12–16px | #f2f2f7 + 白卡圆角 14（已接近） |
| KPI 卡 | **柔和多彩渐变底 + 大数字 + 右侧同色系淡图标**（蓝/紫/青/粉分类色） | 白底 Statistic + 图标前缀，单色 |
| 空状态 | 统一插画 + 一句话 + CTA 按钮 | 部分有、风格不一 |
| 列表 | 筛选行(查询/重置/展开) + 表格或"资源行卡片" + 统一分页 | 有但各页骨架不统一，缺"展开"收纳 |
| 主操作 | 一律右上主按钮（新建X/导出X） | 基本一致 |

### P0 · 第一批（低风险、高感知）

| # | 借鉴点 | 参考做法 | 我们对应 | 动作 |
| --- | --- | --- | --- | --- |
| 1 | 学生首页「待办聚合」 | 首页 = 待完成任务卡（最近的进行中考试/未交卷）+ 最近考试 + 通知公告 + 右侧我的数据 | pages/student/Home.tsx 只有 4 张静态统计卡 | 首屏改为：**进行中/待入场考试卡** + 成绩/收藏统计 + 通知摘要 |
| 2 | 教师首页工作台 | KPI 色彩卡（我的课程/学生/试卷/考试/发布数）+ 教学数据趋势（分指标切换柱状图）+ 最近访问 + 通知公告 + 右栏快捷入口 | pages/teacher/Dashboard.tsx 仅 4 Statistic + 最近考试表 | 加：**发布数 KPI**、近 7 天提交/成绩趋势图（recharts 已在用）、快捷入口（发起考试/组卷/导入学生）、通知聚合 |
| 3 | 统一列表页骨架 | 标题 + 筛选行（查询/重置/**展开**）+ 表格 + 统一分页（第X-Y条/共Z条 + N条/页 + 前往） | 各页风格不一、无统一组件 | 抽一个 `ListPageLayout`/`FilterBar` 公共组件，先套到考试/题库/学生 3 个高频列表 |
| 4 | 空状态统一 | 插画 + 一句话 + 引导 CTA（"暂无场次→请先添加场次"） | 有 Empty，风格不一 | 统一空状态组件（插图 + 主 CTA 直达操作） |
| 5 | 表单细节包 | 标签上置 + 红色 * 必填 + 字符计数（0/30）+ 时间范围日历可清空 + 弹窗内**多行批量添加**（一次加多个场次/考场） | 部分有 | 先补字符计数与时间范围清空；考场/场次批量加行（若有需要） |

## 四、不建议照抄

1. **桌面客户端作答形态**：参考产品的考试在学生机上的「机房/考试专版」WPS 客户端里作答（网页只负责发起与监考），学生点"开始作答"会拉起本地 WPS Office。我们是纯浏览器方案（iframe + 独立窗口 + 服务端实时预览兜底），这条业务前提不同，**其客户端相关交互（打开客户端弹窗、客户端托盘提示）不适用**。
2. **课程中心模型**：把考试挂在课程下的两级结构——我们以考试为核心组织工作流，不重构 IA。
3. **营销与产品线入口**：hero 轮播、体验中心（comate/灵犀/KOS 认证）——考试系统不需要。
4. **整卷抽卷几率**替换题位抽题：整卷粒度更粗；我们保留题位模型（等值替换 + 幂等快照），仅把"几率"作为可选的出卷模式。
5. 其设计中的**强蓝品牌色**不必替换我们的 #007aff——重点是把我们自己的两套旧蓝统一掉。

---

## 五、建议落地批次

- **批次 1（UI 骨架）**：统一列表页骨架 + 空状态组件 + 表单细节包 + 学生首页待办聚合 + 教师首页 KPI/趋势。
- **批次 2（考务贴合）**：监考详情重构（时间线 + 干预动作 + 概况四指标）、成绩表状态列、作答前页题目构成、题库知识点树。
- **批次 3（可选）**：卡片视图、整卷抽卷几率模式、教师预览学生视角。
