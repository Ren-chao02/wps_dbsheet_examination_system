# 「WPS 教学平台」UI/UX 借鉴方案

> 调研对象：https://edu.wps.cn/app/study-platform（教师端 + 学生端）；官方操作手册 https://p.kdocs.cn/s/2OXD2DZIADAB6
> 调研方式：真站登录逐页截图（`test_screenshots/wps-ref/live-*.png`）+ 手册全量翻页（`A-*.png`/`B-*.png`）+ 手册内嵌原图全分辨率导出（`manual-imgs/M-01~M-82.png`，关键图已人工复核）
> 结论用途：确认「抄什么、怎么抄、不抄什么」后再动代码。

---

## 一、总体判断

**可以借鉴，价值主要在「考务业务细节」和「首页/列表的产品化程度」两个层面；整体 IA 和桌面客户端形态不抄。**

1. **信息架构**：参考产品是「课程中心」模型（课程下挂 测验/考试/班级/监考/成绩）。我们以考试为中心组织模块，不照搬；但**「学生端待办聚合首页」「考试配置向导常驻状态条」「监考详情三栏」三个结构可直接吸收**。
2. **视觉与组件**：他们的设计语言（浅灰底 + 白卡大圆角 + 柔和多彩 KPI 卡 + 插画空状态 + 卡片式资源列表）比我们更统一。我们布局层是 Apple 风但沉浸式考试页残留旧 antd 蓝，**建议先统一自身视觉，再吸收他们的卡片/空状态/列表行**。
3. **考务细节**（最值钱）：考前入场动线、答题卡按题型分组、监考考生动态时间线、续考/强制交卷、成绩表「缺考/是否作弊/重新算分」、导出作答文件、场次考场批量录入与规则前置文案、学情四级下钻——**这些与我们业务同构，是逐条可对照补齐的功能缺口**。

## 二、参考产品速写

### 2.1 信息架构

**教师端**（左侧图标栏，展开为完整菜单，导航后自动收起）：

```
首页（工作台）｜ 我的课程 ｜ 在线考试 ｜ 监考管理
官方资源 ▾（官方题库/官方试卷库/官方课程库）
校本资源 ▾（校本题库/校本试卷库/校本组卷方案）
任务中心
底部：切换到学生端 ｜ 用户信息（角色标签 + 学校）
```

**学生端**极简：`首页 / 我的课程`；考试与测验沉在首页待办卡与课程目录树里。

**课程内页**（教师）：课程介绍 / 课程学习 / 实训测验 / 课程班级 / 在线考试 / 监考管理 / 学习统计 / 成绩管理。

### 2.2 设计语言对照

| 维度 | 参考产品 | 我们现状 |
| --- | --- | --- |
| 主色 | 深蓝 #2663db/#2b5cff | #007aff（布局层）与 #1890ff（沉浸页）并存，不一致 |
| 页面底 | #f5f7fa 浅灰，白卡圆角 12–16px | #f2f2f7 + 白卡圆角 14（已接近） |
| KPI 卡 | 柔和多彩底色 + 大数字 + 右侧同色系淡图标（蓝/紫/青/粉分类色） | 白底 Statistic 单色，无分类色 |
| 空状态 | 统一插画 + 一句话 + CTA | 部分有、风格不一 |
| 列表骨架 | 标题 → 筛选行(查询/重置/**展开**) → 表格/卡片 → 统一分页 + 右上主操作 | 各页骨架不统一，缺「展开」收纳 |
| 资源列表 | **卡片式**（题干摘要/封面 + 题型难度状态标签 + hover 浮现操作） | 以表格为主 |

## 四、不建议照抄

1. **桌面客户端作答形态**：参考产品考试在「机房/考试专版」桌面客户端里作答（网页只负责发起和监考，点开始作答会拉起 WPS 客户端、URL 协议唤起）。我们坚持纯浏览器（iframe + 独立窗口 + 服务端实时预览兜底），**客户端相关的交互设计不适用**；但"打开考生文件夹/启动 WPS"这类实操题辅助入口的思路可转化为我们的"打开表格/独立窗口"按钮组。
2. **课程中心 IA**：不把考试重构到课程下。
3. **营销位**：hero 轮播、体验中心（comate/灵犀/KOS）等运营位不需要。
4. **整卷抽卷几率**替换题位抽题：整卷粒度粗于我们"题位 + 等值替换"；仅作为可选出卷模式。
5. **品牌色**：不替换 #007aff；重点是消除我们内部两套蓝色的不一致。
6. **顺带检查项（反面素材）**：手册里平台测试环境右上角常驻 `test | 构建时间` 水印——上线前确认我们所有调试标记/构建信息不出现在师生可见界面。

## 十、官方题库落地 + 认证题库导入（2026-10-11）

**背景**：用户提供两份 Excel 题库（`多维表格考试题库.xlsx` / `飞书多维表格技能认证_考试题库.xlsx`，位于仓库根目录），要求把单选/多选/判断加入「官方题库」；经确认落地方案为「题目加来源字段 + 题库页页签」，品牌词口径为**一并中性化**。

**数据模型**
- `Question.source`（`VARCHAR(16)`，默认 `school`）：`official` = 官方题库（平台统一维护，教师端编辑/禁用/删除置灰，服务端所有权校验同样拦住非 admin），`school` = 校本（教师自建）。
- 迁移 `20261011210000_add_question_source`（`migrate deploy` 应用，非交互环境注意 `migrate dev` 不可用）。

**导入脚本** `packages/server/scripts/import-official-questions.ts`（默认试运行，`--commit` 才写库：
- 读取 `单项选择题/多项选择题/判断题`（OLAP 表为判断格式，按判断题收；公式简答/实操不在范围）。
- **导入 199 题**：单选 83 · 多选 45 · 判断 71；去重后无重复行；判断题答案的 √/×/正确/错误 四种写法、多选答案的 `ABCDEFG` 与 `A、B、C` 两种格式都覆盖。
- 文本中性化 **23 处**（`utils/official-question-import.ts` 的 `neutralizeBrand`：「飞书多维表格」→「多维表格」，其余「飞书」字样一并清除；复核后 0 残留、0 其他品牌词）。
- `title` = 题干原文、`description` 置空（学生端标题即题干，避免重复展示；超 512 字才用 description 兜底）；`analysis` = 解析；知识点列进 `tags` 保留原始信息（不做分类映射）。
- 幂等：`--commit` 先整体清除 `source='official'` 再写入（官方题库完全由脚本托管）；解析失败或数量异常（<100）自动中止。

**界面**
- 题库页顶部新增页签「全部｜官方题库｜校本题库」（`GET /api/questions?source=`）；题干流里官方题带橙色「官方」标签、创建人显示为「官方题库」；详情抽屉新增「来源」与「解析」区块。
- 学生答题页对空 `description` 不再渲染空白题干卡片（导入题的题干就是标题）。

**验证**：两端 tsc 通过；服务端 370 用例（新增 12：中性化/答案解析/构建校验 10 + source 过滤 2）、客户端 52 用例全绿；浏览器实测页签过滤、官方标签与操作置灰、详情解析展示；组卷规则行的可用题数从 `/1` 跳至 `/84`（官方单选题进入抽题池的端到端确认）。
